Relevé mécanique complémentaire aux arbitrages sémantiques des [contrats proposés](contrats.md) et des [commandes existantes](existantes.md). Les noms d’options proviennent des lignes de déclaration de l’aide des binaires GNU installés, du synopsis mdoc FreeBSD 14.3 et des déclarations clap de uutils 0.1.0. Une cellule vide de preuve indique une extraction non applicable ou incomplète. Les tables ne promettent pas la prise en charge de ces options sur NovaOS. Les alias générés, options conditionnelles, opérandes d’expressions et fonctionnalités propres à un OS nécessitent un essai individuel. Pour find et awk, notamment, les opérateurs du langage dépassent les options du lancement.

## Témoins exécutés sur l’hôte

Sur macOS 27.2.1 ( build 26B131, machine arm64), GNU et les commandes système ont été exécutés sur les mêmes entrées octet par octet en locale C. Les deux uname -s rendent Darwin et code 0 ; sort -n ordonne 2 avant 10 ; grep -F sans correspondance rend 1 ; uniq -c compte les trois groupes 2, 1, 1, avec une largeur de préfixe différente. Comparer la valeur et, lorsque le format doit être stable, aussi les octets. Les exécutables hôte ont leur version propre (notamment GNU coreutils 9.12), distincte des instantanés source retenus.

Huit témoins Darwin séparés pour uname, sort, grep, uniq, cut, tr, sed et awk ont produit le code et la sortie attendus sur ARM64 et x86_64 sous Rosetta. Ils constituent des oracles d’hôte. Les observations ne mesurent pas la compatibilité d’un port NovaOS. Consulter les argv, octets et codes dans `hote/oracles-2-isa.json` et `hote/comparaisons.txt` des preuves.
