## Livrable officiel

1. Le lot comprend l’archive source `nova-system-0.2.0.tar.gz` et son fichier `.sha256`. Ses 23 fichiers comprennent les types publics, le code Rust, les déclarations binaires, le transport fichier, les sources de l’exemple, son manifeste et son verrou Cargo, le script de liaison, le lanceur de construction, le guide et la licence MIT. L’archive de 21 237 octets a pour SHA-256 `6feff113b64eef2352c430fc5c64fc2f1f865cfe40339ecbec5e6a4f3ff469a4`. [Archive](../../distribution/sdk/nova-system-0.2.0.tar.gz) · [Empreinte](../../distribution/sdk/nova-system-0.2.0.tar.gz.sha256)
2. Le manifeste rattache cette archive au commit de fusion des sources, aux deux cibles Rust, à la recette et à la chaîne qualifiée. La compilation hors ligne requiert les cibles déjà installées sur l’hôte. Le guide explique aussi comment compiler un projet tiers distinct de l’extraction et générer la documentation avec `rustdoc`. Les ELF de qualification sont identifiés par leurs empreintes. [Guide de compilation](sdk-rust-v0.20.0.md) · [Sélection des composants](../../distribution/manifests/novaos-0.20.0-sdk.json)
3. L’inventaire des API, le rapport de qualification et les relevés d’interopérabilité accompagnent l’archive. Le SDK vise des exécutables natifs NovaOS. Il ne fournit ni runtime Rust `std`, ni chargeur de binaires Linux. L’allocateur général pour applications, le TLS du compilateur et l’admission d’un exécutable depuis P9 ne font pas partie de l’archive. Les compilateurs Rust/C/C++ exécutés sous NovaOS relèvent de la stable serveur v0.30.0. ## Décisions et exclusions

La MOE stabilise quatre garanties du droit de jonction. Le thread possède le handle, le conserve après annulation de son attente, peut le transférer dans le même processus et peut en recueillir le résultat exactement une fois. Les signatures et types Rust, y compris `JoinHandle`, `join`, `detach`, `Result` et `Error`, demeurent expérimentaux. Une mise à jour du SDK doit préserver les quatre comportements et peut demander une adaptation du code source. Les futures API d’erreur pourront préciser l’origine, le code et le contexte. La longueur lue avant une erreur, le droit conservé par le service après une fermeture refusée et les droits de fichiers persistants restent des questions ouvertes pour un mandat ultérieur. [Contrat public](contrat-public-rust-v0.20.0.md)

Le SDK cible des ELF NovaOS statiques sur AArch64 et x86_64. Le jalon exclut Rust `std` complet, le TLS automatique du compilateur, les compilateurs Rust/C/C++ exécutés sous NovaOS, la gestion complète des comptes et ACL, la compatibilité binaire Linux et l’interface graphique. Le support installable UTM qualifié reste en v0.17.0. Une nouvelle distribution pourra faire l’objet d’un mandat dédié. La première stable serveur en mode texte reste fixée à v0.30.0. Le démarrage de v0.21.0 relève d’une nouvelle décision MOA/MOE. [Feuille de route serveur](reconciliation-v0300/README.md)
